# 2026-09-15 工作日志

## 插件系统：开放「详情页」接线

需求：主程序此前只开放了部分插件能力，本次补齐**详情页（IDetailPage）**，让插件在右键组件时能在灵动岛按自定义尺寸展开内容。

### 改动（3 个文件）

1. `Plugin/PluginHost.cs` —— 详情页状态中枢
   - 新增字段 `_activeDetailWidgetId` / `_activeDetailPage`，事件 `DetailPageChanged`。
   - `OpenDetailPage(widgetId)` 真正实现：从 `_widgets` 找到组件 → 取 `DetailPage` 并缓存实例（避免每帧 new）→ 记录状态。返回 bool。
   - `CloseDetailPage()` 真正实现；新增 `ToggleDetailPage(widgetId)` 供右键开/关。
   - `ActiveDetailPage` / `ActiveDetailWidgetId` / `HasActiveDetailPage` 供渲染侧与窗口读。
   - `UnregisterPlugin` 中：若被卸载插件正开着详情页，同步清空（否则强引用会锁住可回收 ALC，热重载泄漏）。

2. `Renderer.cs` —— 尺寸 + 绘制 + 命中
   - 新增 `RefreshDetailPageState()`（每帧最先调用）、`TryGetDetailPageSize()`、`ActiveDetailWidth/Height`、`HasActiveDetailPage`、`ConsumeDetailCloseRequest()`。
   - 尺寸只在详情页实例变化时测量一次；裁剪为宽 180~1000、高 48~480。
   - `WINDOW_WIDTH` / `MAX_WINDOW_HEIGHT` 计入详情页尺寸（底层缓冲会随之自动重建）。
   - `Draw` 在 Toast 分支之后插入详情页分支：整块岛体交给 `IDetailPage.Draw`，然后 3 次 Restore + return。
   - `DrawDetailPage` 登记命中矩形；`DispatchDetailPageClick` 做 `HitTest` + `OnAction`。
   - `DispatchPluginRightClick` 改为返回「命中且提供详情页的组件 Id」。
   - 详情页 Measure/Draw 抛异常 → 熔断（`MarkDetailBroken`）+ 请求宿主收起。
   - `InvalidatePluginHitAreas` 每帧顺带清空详情页命中区。

3. `NotchWindow.cs` —— 交互与尺寸决策
   - RenderLoop 开头先 `RefreshDetailPageState()`，并消费熔断收起请求。
   - `detailOpen` 时岛体尺寸 = 详情页尺寸（Toast 优先级更高）。
   - `shouldHide` 增加 `!HasActiveDetailPage`。
   - 鼠标移出岛体 + 按左键 → 收起详情页。
   - WM_LBUTTONDOWN：详情页展开时岛内左键只走 `DispatchDetailPageClick` 并消费。
   - WM_RBUTTONDOWN：命中带详情页的组件 → `ToggleDetailPage` 并消费（不再弹设置窗口）；详情页已展开时岛内右键直接收起。
   - WM_MOUSEMOVE：详情页展开时跳过原生悬停判定（避免幽灵手型）。
