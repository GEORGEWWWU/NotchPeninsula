# 2026-09-19

## 修复：纯媒体控制器下右键被媒体标题热区整片吃掉

**现象**：只开媒体控制器（无插件组件）时，岛内右键打不开设置窗口，必须精确点到岛体最右侧那条窄边才行。

**根因**：提交 `05df004` 给「折叠态媒体标题」加了右键 → 展开媒体面板的快捷入口。
该热区按「本帧真的画了标题文字」登记，高 = 整个岛体高、宽 = 文字宽度；
纯媒体控制器时没有插件预留区（`GetPluginRowReserve() == 0`），文字铺满整条岛体，
于是右键被整片消费，只剩右侧 10~40px（频谱/按钮区）能落到 `ConsoleWindow.Toggle()`。

**改动**（最小化，只影响纯媒体控制器形态）：
- `Renderer.cs`：新增 `public static bool HasPluginRowContent => GetPluginRowReserve() > 0f;`（约 487 行）
- `NotchWindow.cs` `WM_RBUTTONDOWN`：媒体标题展开分支加前置条件 `Renderer.HasPluginRowContent`
  → 有插件组件时行为完全不变；纯媒体控制器时右键直接打开设置窗口（恢复默认交互）
- 文档同步：`README.md` 第 58 行、`NPS_PluginsAPI.md` 第 356 行附近说明门控条件

**验证**：`dotnet build -c Debug` 成功，0 警告 0 错误。（未跑无头冒烟测试，本改动是纯 WndProc 条件门控。）

**约定**：岛内右键是分层消费的 —— 详情页 → 媒体标题热区 → 插件组件广播 → 设置窗口。
给原生区域加「消费型热区」前，必须先算它在无插件形态下会不会把整岛吃光。
