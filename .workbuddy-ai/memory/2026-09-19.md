## 修复：纯媒体控制器下右键被媒体标题热区整片吃掉

**现象**：只开媒体控制器（无插件组件）时，岛内右键打不开设置窗口，必须精确点到岛体最右侧那条窄边才行。

**根因**：提交 `05df004` 给「折叠态媒体标题」加了右键 → 展开媒体面板的快捷入口。
该热区按「本帧真的画了标题文字」登记，高 = 整个岛体高、宽 = 文字宽度；
纯媒体控制器时没有插件预留区（`GetPluginRowReserve() == 0`），文字铺满整条岛体，
于是右键被整片消费，只剩右侧 10~40px（频谱/按钮区）能落到 `ConsoleWindow.Toggle()`。

**改动**（最小化，只影响纯媒体控制器形态）：
- `Renderer.cs`：新增 `public static bool HasPluginRowContent => GetPluginRowReserve() > 0f;`（约 487 行）
- `NotchWindow.cs` `WM_RBUTTONDOWN`：媒体标题展开分支加前置条件 `Renderer.HasPluginRowContent`
  → 有插件组件时行为完全不变；纯媒体控制器时右键直接打开设置窗口（恢复默认交互）
- 文档同步：`README.md` 第 58 行、`NPS_PluginsAPI.md` 第 356 行附近说明门控条件

**验证**：`dotnet build -c Debug` 成功，0 警告 0 错误。（未跑无头冒烟测试，本改动是纯 WndProc 条件门控。）

**约定**：岛内右键是分层消费的 —— 详情页 → 媒体标题热区 → 插件组件广播 → 设置窗口。
给原生区域加「消费型热区」前，必须先算它在无插件形态下会不会把整岛吃光。

## 修复：展开的媒体面板 / 插件详情页不随鼠标离开自动收缩

**现象**：媒体控制面板与插件详情页展开后，鼠标移开岛体不会收，得点岛外才收。

**根因**：提交 `2896dbe` 把收起策略统一改成「岛外点击才收」，为此在 `WM_MOUSELEAVE` 里
注释掉了 `IsMediaExpanded = false`，详情页也不再跟 `!_isHovered`。

**改动**（`NotchWindow.cs`，抽出两个方法统一触发点）：
- `CollapseExpandedPanels()` = 媒体面板 + 插件详情页；`CollapseAllExpanded()` = 前者 + `_isManuallyExpanded`
- `WM_MOUSELEAVE` → `CollapseExpandedPanels()`（主触发；分层窗口透明像素不吃鼠标消息，
  系统派发的 MOUSELEAVE ≈「真的离开岛体」）
- `WM_LBUTTONUP`（拖时间轴后）→ `!_isHovered` 时补一次（拖动期间的 MOUSELEAVE 被「拖动中不收起」吃掉）
- `RenderLoop` 轮询块：加 `!_media.IsDragging` 前置（否则拖时间轴划出岛体会把面板从手里抽走），
  岛外点击仍走 `CollapseAllExpanded()`（保留 `_isManuallyExpanded` 语义不变）
- 文档同步：`README.md` 功能列表、`NPS_PluginsAPI.md` 第 362 / 447 行

**⚠️ 刻意没做的事**：`_isManuallyExpanded`（自动隐藏的点击唤醒）**不跟**鼠标离开收起。
唤醒是「点顶部细边 → 岛体滑下来」，滑下来后光标天然在岛体上方，挂上去会变成点一下闪一下。

**验证**：`dotnet build -c Debug` 成功（0 警告 0 错误）。

**踩到的坑**：`%TEMP%\np-smoke` 无头冒烟测试工程**已经编译不过**（43 个错误，全是给早已从本仓移除的
拖放实现写的断言，如 `Win32.DROPEFFECT_COPY` / `IDropTarget`）。`dotnet run --no-build` 会静默跑
旧二进制并打印「全部通过 ✅」—— 是假绿灯，别拿它当验收依据。已把这一点写进 skill。

## 追加：插件详情页改为延迟 0.9s 收起

**原因**（用户 2026-09-19）：详情页尺寸由插件决定，可能比展开前的岛体更窄/更矮，展开动画一结束，
原本停在岛体边缘的光标就落到岛外 → 上一版会「刚点开就自己没了」。

**改动**（`NotchWindow.cs`）：
- 新增 `DetailCollapseDelayMs = 900`、`_detailCollapseDeadline`、`_detailCollapseWidgetId`
- `CollapseExpandedPanels()`：媒体面板仍**立即**收；详情页只挂 `now + 900ms` 时间戳
- 新增 `TickDetailCollapse()`，RenderLoop 每帧结算（没任务时一次 DateTime 比较就返回）
- 取消点：`WM_MOUSEMOVE` 的 `!_isTrackingMouse` 分支（鼠标回到岛上）
- 到期只收「当初挂时间戳的那张详情页」（比对 `PluginHost.ActiveDetailWidgetId`），
  防止 0.9s 内插件换页被顺手收掉
- 岛外点击仍走 `CollapseAllExpanded()`：立即收、并清掉挂起的延迟任务
- 文档同步：`README.md`、`NPS_PluginsAPI.md` 第 362 / 447 行

**验证**：`dotnet build -c Debug` 成功（0 警告 0 错误）。

## 返工：右键媒体控制器彻底不能展开（上一版门控方案作废）

**用户反馈**：上一版给媒体标题右键展开加的门控 `HasPluginRowContent` **没生效** ——
用户环境里有插件组件，门控照样放行，右键到标题/歌词文字仍然展开，只有空白处才开设置窗口。

**教训**：用「某些情况下才放行」的门控去救一个**覆盖整岛高度的大热区**是错的方向。
用户的诉求是「这块区域根本不该有这个行为」，不是「少触发几次」。

**最终改动**（整套机制删除，不留死代码）：
- `NotchWindow.cs` `WM_RBUTTONDOWN`：删掉「右键折叠态媒体标题 → 展开媒体面板」整个分支。
  现行优先级：收起详情页 → 插件组件广播 → `ConsoleWindow.Toggle()`
- `Renderer.cs`：删除 `_mediaTitleHit` 字段、`HitMediaTitle()` 方法、`Draw()` 里的热区登记块、
  帧首作废行、`HasPluginRowContent` 属性；原处留注释说明「为什么故意没有右键热区」
- 副作用（已知、可接受）：**直接交互模式（MediaInteractionMode == 0）不再有任何展开面板的入口** ——
  该入口本就是 `05df004` 当天才加的，删掉即恢复其之前的状态
- 文档同步：`README.md` 功能列表、`NPS_PluginsAPI.md` 第 354 行右键分层说明

**验证**：`dotnet build -c Debug` 成功（0 警告 0 错误）；全仓 `grep HitMediaTitle|HasPluginRowContent|_mediaTitleHit` 无代码残留。
